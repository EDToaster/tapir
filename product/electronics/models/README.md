# Portable component models

Ten local B-reps are bound to nine footprints (the Choc footprint carries a switch and a cap). Seven are unmodified library models; three are explicitly named fit models constructed here. All model offsets and rotations are zero, all scales one. A bare host-wire pad array and carrier mounting holes have no purchased component body. The separate Sprintek, cell, leads, case, and removable parts belong in the mechanical assembly, not on these unrelated footprint model slots.

Coordinates below are in mm relative to the component-side carrier face, equivalent to KiCad STEP local coordinates: +X follows editor +X, +Y is the negative of editor Y, and +Z is out of the mounted face. KiCad applies the footprint position, orientation and any bottom-side flip. Do not reapply that transform to a populated board export. The `bbox_min_mm` and `bbox_max_mm` in `manifest.json` were measured after re-opening each shipped STEP with OCCT; they are not physical caliper measurements or tolerance guarantees.

## Regeneration and model identity

From the repository root, with the Python environment from `mechanical/stack/requirements.lock` activated:

```sh
M=product/electronics/models
python "$M/model_catalog.py" verify
python "$M/model_catalog.py" fetch /tmp/tapir-public-model-check
python "$M/generate_fit_models.py" --out /tmp/tapir-regenerated
python "$M/model_catalog.py" compare-regenerated /tmp/tapir-regenerated
```

The first command enforces the exact shipped SHA-256, valid positive-volume solids, incoming Choc conductive-pin positions, measured bounds/volume, and all native footprint model bindings. The second reacquires just the seven redistributable assets at pinned commits and refuses hash drift. The third regenerates only project-authored proxies. OCCT can reorder color presentation records between runs; the final command checks the SHA-256 of the full pre-presentation B-rep/assembly data, names, positions, plus independent volume, solid count and bounds, rather than accepting a matching outer box alone. The format is STEP AP214 with millimetre geometry. A deliberate new approved model revision requires changing its pinned hash and issuing a fresh `emit-manifest`; it is not a way to accept an unexpected upstream revision.

The [Seeed Plus host archive](https://files.seeedstudio.com/wiki/XIAO-KiCad-Library/New_XIAO_Series_Footprints.zip) contains active SAMD21 and hidden base nRF/RP2040 references, not an exact Plus assembly. Those references are explicitly removed by the footprint generator; the audit rejects extras and hidden substituted files. The [non-Sense Plus board](https://files.seeedstudio.com/wiki/XIAO-BLE/Seeed_Studio_XIAO_nRF52840_Plus.zip) shares footprints for optional Sense circuitry, which are not proof of fitted sensors. Its USB Fab bounds and pad drill locations, not the unrelated linked models, informed this fit envelope. Acquire private comparison inputs if needed, for example:

```sh
python "$M/model_catalog.py" private-reference /tmp/tapir-reference seeed-plus-v11.zip
python "$M/model_catalog.py" private-reference /tmp/tapir-reference seeed-host.zip
# Only if your use is covered by FKcaps's rendering terms; never share conversions:
python "$M/model_catalog.py" private-reference /tmp/tapir-reference fk-mbk-1u-render-only.stl
# Only if your intended use is licensed; not bound, converted or redistributed:
python "$M/model_catalog.py" private-reference /tmp/tapir-reference jst-third-party-private-review.step
```

The optional original inputs stay outside the repository. The complete source URLs, SHA-256 values, exact footprint names, transformations, usage status, measured extrema, and volume/solid counts for the ten shipped models are in `manifest.json`. These measurements do not resolve sample variation, supplier availability, injection-mold details, battery safety, tool access or contact clearances during travel.
